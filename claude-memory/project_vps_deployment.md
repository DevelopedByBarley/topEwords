**Deploy = Ploi pulls from GitHub (DevelopedByBarley/topEwords, main) and runs the deploy script:** `git pull` → `composer install --no-dev --optimize-autoloader` → `npm ci` → `npm run build` → `php artisan migrate --force` → `config:cache` + `route:cache` + `view:cache` → `service php8.4-fpm reload`. To deploy a code fix: commit + push the relevant files to main, then click Deploy in Ploi (or SSH `git pull && php artisan migrate --force`).

**BUGS HIT & FIXED during this deploy (all committed to main):**
1. **Vite build failed — `driver.js` not resolved.** It was installed locally but missing from package.json, so `npm ci` didn't fetch it. Fix: `npm install driver.js@^1.4.0 --save` (→1.6.0), committed package.json + lock. (commit 228d074)
2. **MySQL rejects JSON column defaults (error 1101).** `flashcard_settings` + `flashcard_deck_settings` migrations had `$table->json('learning_steps')->default('[1, 10]')`. Works on local XAMPP (MariaDB stores json as `longtext` + `json_valid` CHECK and ALLOWS a literal default) but MySQL 8 forbids defaults on JSON/TEXT/BLOB. Fix: removed `->default()` from both migrations, moved the default to `$attributes = ['learning_steps' => '[1, 10]']` on both models. (commit 584a92d) **General rule: never put a DB-level default on a JSON column — MariaDB allows it, MySQL doesn't. Default belongs on the model.** ALSO removed the default from the **local dev MariaDB** permanently (`ALTER TABLE … ALTER COLUMN learning_steps DROP DEFAULT` on both tables) so future phpMyAdmin/mysqldump exports from local are already MySQL-clean — no more per-export sed needed.
3. **HTTP 502 "upstream sent too big header".** nginx header buffer too small for Laravel/Inertia response headers (large Set-Cookie/session). The Ploi config had `fastcgi_buffers 32 32k` but NO `fastcgi_buffer_size` (the dedicated *header* buffer — separate from `fastcgi_buffers` which is for the body). Fix in `/etc/nginx/sites-available/topwords.eu` (Ploi → Nginx Configuration): `fastcgi_buffer_size 128k; fastcgi_buffers 4 256k; fastcgi_busy_buffers_size 256k;` then `nginx -t` + reload. This is a server-config fix (not in git).
